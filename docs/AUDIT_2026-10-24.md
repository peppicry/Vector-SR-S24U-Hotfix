# Repository audit — 2026-10-24

Audited repository snapshot: `peppicry/Vector-SR-S24U-Hotfix` at `1621db6b2ec6b7daebd35b6aacfcd57dd6f9e556`. All 11 tracked files, both workflows, the patch's upstream execution path and the published 3136 release/source archives were inspected. The companion One UI X release inventory was checked for the historical download links. This is not a complete audit of every upstream Vector-SR/third-party implementation or an on-device test.

## Verdict

The primary hotfix is coherent and present in both the published source and compiled DEX. Its exact log-generation scenario remains reproducible in an isolated Java test against current official code. The repository is not free of defects: release preservation, version identity, a null-logging regression, patch preflight and source rebuild instructions need correction.

## Findings in the audited snapshot

1. **High — historical release can be replaced.** `build-device-tested.yml` hardcodes the 3136 tag, force-moves an existing tag and uploads with `--clobber`. A future run can replace the release intended to remain available to One UI 8.5 users. The proposed candidate uses a separate tag, refuses existing tags/releases and publishes only when explicitly selected in workflow dispatch.

2. **High — immutable source pin does not fix the module version.** The workflow checks out 3136, but upstream Gradle counts `refs/remotes/origin/master`, which can advance independently. At this review, the source pin has 3136 commits while official master has 3151. A rebuild can consequently label old source with a newer version while the archive names/metadata still say 3136. Both proposed workflows verify the expected identity and reset only the checkout's local tracking reference to the pinned HEAD before Gradle runs.

3. **Medium — `XposedBridge.log((Throwable) null)` now throws.** The original upstream delegates to Android's null-tolerant `Log.getStackTraceString`; the hotfix dereferences `t.getClass()` first. The host-JVM control accepted null on official code, threw `NullPointerException` with the current hotfix and accepted null after adding the proposed `t != null` condition. The [Android 16 Log implementation](https://android.googlesource.com/platform/frameworks/base/+/android16-qpr2-release/core/java/android/util/Log.java) explicitly handles a nullable throwable. This is a confirmed Java API behavior regression; no frequency or device impact is claimed.

4. **Medium — a source archive alone does not restore build identity.** The public source ZIP includes the checked-out submodules, but no `.git` history or S24U-specific rebuild instructions. Its Gradle version providers still require Git refs/tags. The proposed package includes the exact hotfix script, submodule revisions and [rebuild instructions](BUILDING.md) that restore the pinned history and local version reference. No byte-for-byte build reproducibility claim is made.

5. **Low — failed patch application can leave a partial edit.** The current script writes `LegacyDelegateImpl.java` before validating the `XposedBridge.java` anchor. A deliberately changed second anchor caused failure after the first file had been changed. The build stops, so this test did not produce an invalid published binary. The proposed script validates exactly one anchor in both files before writing either, with explicit UTF-8/LF output; the same failure leaves both files unchanged.

6. **Traceability gap — original test file and public release differ.** The README's original device-test ZIP hash starts `f2d7e6a2`; the currently published 3136 ZIP starts `77db8d57`. The latter independently matches the GitHub asset digest and published manifest. Different digests establish different files, not a broken hotfix. The proposal records both identities and keeps the existing public release unchanged. A matching original test ZIP was not located in the searched current-workspace directories.

7. **Known scope limit — bypass and logger have different matching boundaries.** The bypass checks method name and first argument, without checking declaring class; a same-named method in another class can match. The logger filters the exact exception class/message from any legacy source. This is consistent with the current patch and its historical review, but is broader than a class-specific Samsung framework check. The proposal does not silently change the device-tested matching policy; narrowing it needs an actual affected-framework/module trace and fresh device validation.

## Checks that passed

- Every file in the published `SHA256SUMS.txt` matched after download: binary, source ZIP, patch and metadata.
- All **27** embedded module `.sha256` sidecars matched their payloads; every module payload had a sidecar and no duplicate archive entries were found.
- `module.prop` reports `v1.2 (3136)` / `versionCode=3136`.
- Compiled DEX disassembly contains the method-name/first-argument guard, original-call fast path and exact exception/message logging filter. It also confirms the missing null check in the published logger.
- Published Java sources match the original Samsung patch. All nine top-level upstream submodules and the nested LSPlant dex_builder have contents in the source archive.
- All **596** top-level tracked upstream blob files were compared with the published source archive: none was missing; only the two intended Java files differed in content. `gradlew.bat` differed only by the CRLF conversion explicitly required by upstream `.gitattributes`.
- The repository license matches pinned upstream byte for byte; attribution and modified-build notices are present. This technical check is not a legal opinion.
- Both original and proposed workflows pass `actionlint 1.7.12`. The proposed workflows align Android SDK setup with upstream's `android-actions/setup-android@v4`.
- Upstream native logging tests pass with address/undefined-behavior sanitizers; daemon startup tests pass with the mount operation mocked.
- The isolated host-JVM scenario, normal lookup controls, unrelated-error controls and null-logging checks were executed. See [the rebase evidence](REBASE_2026-10-24.md).
